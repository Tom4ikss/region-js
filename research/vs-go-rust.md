# Многопоточность: region-js, Go и Rust

Что из привычного по Go и Rust есть в форке, через какой механизм оно работает и сколько
стоит. JS здесь — d8 из этого форка: `spawn`, регионы, каналы, `RwLock`. Rust — `std` и
tokio, Go — стандартная библиотека.

Условия замеров: Apple Silicon (6 производительных и 6 энергоэффективных ядер), V8 собран без
внутренних проверок (`out/fast`: `is_debug = false`, `dcheck_always_on = false`), tokio —
`cargo run --release`, четыре рабочих потока у обоих, лучший из пяти прогонов. Скрипты:
`tests/bench-tasks.js`, `tests/bench-real.js`, `tests/bench-channels.js`, `tests/bench.js`,
`tests/bench-frozen.js`, `tests/bench-pauses.js` и `tests/tokio-bench` (`cargo run --release`
и `cargo run --release -- real`). На Mac Go не мерили: в таблицах ниже его колонка — не замер,
а то, как устроен его рантайм. Замеры с Go — в разделе «Linux x64: JS, Go и tokio» в конце.

В столбце «Есть или нет» порядок всегда JS / Go / Rust.

## Задачи и потоки

| Что | Есть или нет | Через что работает | Замеры |
|---|---|---|---|
| Лёгкие задачи | да / да / да | **JS:** `spawn(fn, ...args)` — задача уходит в пул долгоживущих воркеров (по изоляту V8 на поток, `spawn.poolSize`, по умолчанию 4) через свою очередь, без `postMessage`. **Go:** горутины, планировщик M:N, стек от 2 КБ. **Rust:** `tokio::spawn` — future как конечный автомат в очереди рантайма; `std::thread` — поток ОС | 1000 пустых задач, запустить и дождаться: JS 1,15 мс, tokio 0,26 мс (×4,4) |
| Параллельный счёт | да / да / да | **JS:** задачи на разных изолятах, у каждого своя куча и свой JIT. **Go:** горутины на `GOMAXPROCS` потоках. **Rust:** задачи tokio на worker threads | 1000 задач по 50 мкс счёта: JS 12,6 мс, tokio 12,65 мс — разницы нет |
| Ждать без блокировки | да / не нужно / да | **JS:** `await` на ручке задачи, канале, локе. **Go:** код пишется блокирующим, планировщик паркует горутину. **Rust:** `async`/`.await` | — |
| Блокирующее ожидание | да / да / да | **JS:** `join()`, `recvSync()`, `writeSync()`; поток сначала до 50 мкс крутится, потом спит. **Go:** любой блокирующий вызов. **Rust:** `block_on`, `std::sync`, `blocking_recv` | ping-pong главного потока с задачей, 1000 кругов: JS 1,68 мс, tokio `block_on` 6,4 мс — JS быстрее в 3,8 раза |
| Захват переменных | да / да / да | **JS:** движок разбирает замыкание `fn`, обычные данные копируются в каждую задачу, регионы переезжают. **Go:** замыкание по ссылке, общая память. **Rust:** `move`-замыкание, требуется `Send + 'static` | — |
| Группа задач | да / да / да | **JS:** `JoinSet` (как в tokio), `Promise.all`. **Go:** `sync.WaitGroup`, `errgroup`. **Rust:** `tokio::task::JoinSet`, `join!` | — |
| Отмена | да / да / да | **JS:** `handle.abort()`, `timeout(ms)`; срабатывает на ближайшем ожидании канала или лока, отменяет и вложенные задачи; долгий цикл проверяет `spawn.aborted()`. **Go:** `context.Context`, кооперативно, каждый вызов сам проверяет `ctx.Done()`. **Rust:** `JoinHandle::abort()` на ближайшем `.await`, `tokio::time::timeout` | — |
| Прервать долгий цикл без ожиданий | нет / да / нет | **JS:** функцию посреди работы не прервать. **Go:** асинхронное вытеснение горутин (с 1.14). **Rust:** задача tokio без `.await` занимает поток рантайма | — |
| Много ждущих задач | да / да / да | **JS:** ждущая задача — промис в воркере, не поток. **Go:** припаркованная горутина. **Rust:** future в очереди | JS: 1000 и 100 000 задач, ждущих канал, — около 3 мкс на задачу |

## Данные между потоками

|---|---|---|---|
| Передать данные без копии | да / да / да | **JS:** регион переезжает: меняется владелец в таблице регионов, объекты остаются на месте (O(1)). **Go:** передаётся указатель, кто им дальше пользуется — не проверяется. **Rust:** move, старая переменная недоступна, проверяет компилятор | Дерево в миллион узлов: переезд региона 0,06 мс, structured clone 287 мс. Rust и Go — передача указателя |
| Данные туда и обратно | да / да / да | **JS:** регион уезжает в задачу и возвращается вместе с результатом. **Go/Rust:** указатель, `Vec` | 200 пачек по 1000 заказов, посчитать скидку: JS 13,4 мс, воркеры с `postMessage` 309 мс, tokio 0,7 мс |
| Положить данные в общую память | да / не нужно / не нужно | **JS:** литералы `'use region'`/`#{}` создают объекты сразу в регионе; `region.run()` копирует граф. **Go, Rust:** память и так общая | 200 000 заказов в четырёх потоках и прочитать в главном: JS 38 мс, воркеры 220 мс, tokio 16,5 мс. Копия дерева в миллион узлов в регион — 266 мс |
| Общие данные только для чтения | да / да / да | **JS:** `Region.share(data)` (как `Arc`, навсегда) или `freeze()` + билеты `borrow()`. **Go:** указатель, договорённость не писать. **Rust:** `Arc<T>` | Каталог 100 000 товаров, 4 потока по миллиону чтений: JS 16,7 мс (из них около 11 мс — копия в `Region.share`), воркеры 59 мс, tokio 1,6 мс. Параллельный обход замороженного дерева: ×2,0 на 2 воркерах, ×3,9 на 4, ×5,7 на 8 (6 быстрых ядер) |
| Изменяемые общие данные под локом | да / да / да | **JS:** `RwLock` держит регион; писатель на время становится его владельцем, читатели читают замороженный. **Go:** `sync.Mutex`, `sync.RWMutex`. **Rust:** `Mutex`, `RwLock` (`std`, tokio) | Взять на запись и отпустить ×1000, без соперников: JS 0,19 мс, tokio 0,01 мс. 4 задачи по 250 записей: JS 0,79 мс, tokio 0,07 мс |
| Отдельный `Mutex` | нет / да / да | **JS:** только `RwLock`, его `write()` — то же самое | — |
| Атомики и общая память низкого уровня | да / да / да | **JS:** `SharedArrayBuffer` + `Atomics` (стандарт). **Go:** `sync/atomic`. **Rust:** `std::sync::atomic` | — |
| Защита от гонок данных | да / нет / да | **JS:** у региона всегда один владелец или много читателей; чужое обращение — `OwnershipError`, проверка в рантайме. На `SharedArrayBuffer` гонки возможны, как и в обычном JS. **Go:** гонки возможны, их ловит `-race` в тестах. **Rust:** `Send`/`Sync` и заимствования, проверяет компилятор, в безопасном коде гонок нет | — |
| Цена защиты | есть / — / нет | **JS:** владелец, форма и записываемое значение проверяются в машинном коде; Turbofan в цикле без вызовов проверяет владельца один раз. **Rust:** проверки только при компиляции | Turbofan, наносекунд на обращение, обычный объект против региона: чтение поля 1,5 / 2,1, запись поля 1,4 / 1,6, чтение по индексу 1,5 / 2,5, запись по индексу 1,7 / 2,2. Обход дерева в миллион узлов: ×1,4 к обычным объектам |
| Что можно передать | частично / всё / всё, что `Send` | **JS:** простые объекты, массивы, строки, числа, типизированные массивы, каналы, локи. Функции, `Map`, `Set`, `Date`, экземпляры классов в регион не кладутся; обычные объекты копируются сериализатором | — |

## Каналы и синхронизация

| Что | Есть или нет | Через что работает | Замеры |
|---|---|---|---|
| Каналы | да / да / да | **JS:** `Channel`, с буфером и без; `send`/`recv` через `await` или блокирующие `sendSync`/`recvSync`. Числа, строки, регионы и каналы идут без сериализатора, регионы переезжают. **Go:** `chan`. **Rust:** `tokio::sync::mpsc`, `std::sync::mpsc`, crossbeam | Круг «туда и обратно» через два канала: 1,2–1,8 мкс (как `postMessage` + `getMessage`, 1,2 мкс); с регионом в 1000 узлов — 2,2 мкс. 1000 задач шлют по числу, главный поток читает: JS 1,49 мс, tokio 0,43 мс |
| Разбудить ждущих | да / да / да | **JS:** ждущий поток будится напрямую, значение забирает без общего мьютекса. **Go, Rust:** очередь ожидающих в канале | 1000 задач ждут `recv`, потом их будят: JS 2,05 мс, tokio 0,63 мс |
| Круг между двумя задачами | да / да / да | **JS:** задачи в разных изолятах, каждый круг — пробуждение другого потока. **Go, Rust:** обе задачи могут крутиться в одном потоке, круг — переключение конечного автомата или горутины | 1000 кругов: tokio 0,21 мс внутри рантайма. JS между задачами медленнее примерно в 8 раз |
| Ждать несколько каналов | да / да / да | **JS:** `select`. **Go:** `select`. **Rust:** `tokio::select!` | — |
| Закрытие | да / да / да | **JS:** `close()`; `send` в закрытый канал — `TypeError`, значения ждущих отправителей остаются в канале. **Go:** `close()`; `send` в закрытый — panic. **Rust:** канал закрывается, когда отпущены все отправители; `send` возвращает `Err` | — |
| Поиск дедлоков | да / частично / нет | **JS:** если все потоки 50 мс спят на каналах и локах, все ожидания заканчиваются `DeadlockError`, его можно поймать. | Конец программы | ждёт / не ждёт / не ждёт | **JS:** d8 ждёт задачи и операции на каналах. **Go:** конец `main` завершает все горутины. **Rust:** конец `main` или рантайма | — |

## Память и сборка мусора

| Что | Есть или нет | Через что работает | Замеры |
|---|---|---|---|
| Сборка мусора | да / да / нет | **JS:** у каждого изолята своя куча и своя сборка; регионы лежат в общей куче. **Go:** одна конкурентная сборка на процесс, без перемещения объектов, с короткими паузами. **Rust:** владение и `Drop`, сборки нет | — |
| Мусор одного потока не останавливает другие | да / частично / да | **JS:** обычный мусор собирает его поток; регион, который держит один владелец, этот владелец собирает и помечает сам (шаги 3–6 `research/region-gc.md`), и строки региона умирают вместе с ним. Сборка общей кучи по-прежнему останавливает всех. **Go:** куча общая, паузы короткие для всех, но мусор одной горутины замедляет выделяющих (mark assist). **Rust:** сборки нет | `bench-pauses`, 3 секунды мусора `'use region'` в одном потоке: 0 пауз у остальных; со строками в общей куче (`--no-region-strings`) 7 пауз, 206 мс, самая длинная почти 100 мс |
| Освободить сразу | да / нет / да | **JS:** `region.free()` закрывает регион для всех сразу; память типизированных массивов отдаётся сразу, объектов — на ближайшей сборке. **Go:** нет, только сборка. **Rust:** `drop` | — |

## Итог

- **Против сегодняшнего JS** (воркеры и `postMessage`) регионы быстрее в 3,5–23 раза на
  сценариях с данными: данные переезжают, а не копируются.
- **Против Rust с tokio:**
  - счёт внутри задач идёт наравне;
  - накладные расходы на задачу, канал и лок выше в 3–20 раз: задача и сообщение уходят в
    другой изолят V8, лок меняет владельца региона;
  - работа с данными медленнее в 2–19 раз из-за проверок на каждом обращении и копирования
    данных в регион.
- **Против Go** на разные стороны:
  - Go быстрее и проще: общая память и дешёвые горутины;
  - зато гонки данных в Go возможны, а дедлок роняет программу;
  - здесь гонку данных на регионе не допускает рантайм, а дедлок становится исключением,
    которое можно поймать.
- **По гарантиям** регионы ближе к Rust, но проверяют в рантайме то, что Rust проверяет при
  компиляции, и за это платят наносекундами на каждом обращении.

## Linux x64: JS, Go и tokio

Условия: виртуальная машина, Intel Xeon (Ice Lake), 32 vCPU; d8 — release-сборка без DCHECK,
Go 1.22+ (`tests/go-bench`, `GOMAXPROCS` равен числу потоков), tokio — `cargo run --release`.
У всех четыре рабочих потока и 16 ядер (`taskset -c 0-15`), лучший из трёх прогонов по пять.

| Замер | JS | Go | tokio |
|---|---|---|---|
| 1000 пустых задач, запустить и дождаться | 3,8 мс | 0,5 мс | 0,6 мс |
| 1000 задач по 50 мкс счёта | 13,2 мс | 12,8 мс | 12,8 мс |
| 1000 задач шлют по числу, главный поток читает | 4,9 мс | 0,45 мс | 0,7 мс |
| 1000 задач ждут `recv`, потом их будят | 8,9 мс | 0,7 мс | 2,0 мс |
| 1000 кругов главного потока с задачей | 3,8 мс | 0,35 мс | 13,2 мс (`block_on`), 0,65 мс внутри рантайма |
| Лок на запись и отпустить ×1000, без соперников | 0,47 мс | 0,03 мс | 0,05 мс |
| 4 задачи по 250 записей под локом | 1,8 мс | 0,03 мс | 0,22 мс |
| 200 000 заказов построить в четырёх потоках | 71 мс | 35 мс | 48 мс |
| 200 пачек по 1000 заказов, посчитать скидку | 11,2 мс | 0,9 мс | 1,4 мс |
| Каталог 100 000 товаров, 4 потока по миллиону чтений | 51 мс | 3,9 мс | 4,9 мс |

- Счёт внутри задач у всех одинаковый.
- Задача, канал и лок в JS стоят в 4–60 раз дороже:
  - задача и сообщение уходят в другой изолят, и каждое ожидание — пробуждение другого потока ОС;
    на этой виртуальной машине `spawn` с `await` по одной задаче — около 6 мкс, то есть два
    таких пробуждения;
  - Go и tokio чаще всего передают работу внутри своего планировщика, не будя поток;
  - исключение — круг главного потока с задачей против `block_on` у tokio: там поток будит и
    tokio, и JS быстрее в 3,5 раза.
- Лок без соперников стоит 165 нс на `writeSync()` + `release()`: два вызова API, глобальный
  мьютекс каналов и смена владельца региона. С `using` — ещё около 220 нс: в V8 15.9 каждый
  блок с `using` делает три вызова рантайма, у пустого `try`/`finally` это 1,6 нс.
- Построить заказы в JS — в 1,5–2 раза дольше, остальная работа с данными медленнее в 8–13 раз:
  - в каталоге около 7,5 нс на чтение уходит на `x % c.length`: V8 считает его через `fprem`
    и для обычных массивов;
  - объект региона вдвое больше обычного, поэтому чтений мимо кэша больше;
  - ещё 22 мс — копия каталога в `Region.share()`.
- В пачках заказов на заказ уходит 55–76 нс против 21–22 у тех же обычных объектов. Если всё
  в кэше (2 000 заказов), то 23–42 нс против 9–11: проверки на каждом обращении, значения в
  отдельном массиве, коробки для чисел при записи.

### HTTP

`tests/node/http/run.py rhttp go rust fastify-cluster`: 8 потоков сервера на ядрах 0–15, wrk на
16–31, 256 соединений, 15 секунд на маршрут. Маршруты те же, что в `work.js`:

- `/hello` — маленький JSON;
- `/compute` — 4000 псевдослучайных записей, стабильная сортировка;
- `/catalog` — запрос по одной категории каталога из 1 000 000 строк: около 980 строк отфильтровать,
  отсортировать по цене, выдать пять самых дешёвых.

У Go стабильная сортировка — `slices.SortStableFunc`, у Rust — `sort_by`.

| Вариант | `/hello`, запросов/с | `/compute` | `/catalog` | Память под нагрузкой |
|---|---|---|---|---|
| rhttp (регионы, 8 потоков) | 481 000 | 6 160 | 25 100 | 0,73 ГБ |
| fastify-cluster (8 процессов) | 449 000 | 6 130 | 30 300 | 1,6 ГБ |
| Go `net/http` | 289 000 | 5 080 | 26 700 | 0,32 ГБ |
| Rust axum + tokio | 681 000 | 20 600 | 178 000 | 0,23 ГБ |

При фиксированной нагрузке (wrk2: 40 000, 4 000 и 12 000 запросов в секунду) p99:

| Вариант | `/hello` | `/compute` | `/catalog` |
|---|---|---|---|
| rhttp | 1,9 мс | 10,2 мс | 2,5 мс |
| fastify-cluster | 1,9 мс | 160 мс | 2,3 мс |
| Go | 2,1 мс | 185 мс | 89 мс |
| Rust | 1,9 мс | 2,4 мс | 1,8 мс |

- rhttp наравне с fastify-cluster:
  - `/catalog` на 17 % медленнее: это чтение каталога-региона;
  - памяти вдвое меньше, потому что каталог один на все потоки;
  - хвост `/compute` под фиксированной нагрузкой в 16 раз короче; почему, не разбирали.
- Go быстрее rhttp только на `/catalog`, на 6 %. Хвосты у него длиннее, вероятно, из-за
  сборщика мусора: каталог — миллион указателей.
- Rust быстрее всех в 1,4–7 раз. Почти всё время JS в `/compute` и `/catalog` уходит на
  `Array.prototype.sort` с функцией сравнения: около 17 нс на сравнение (вызов функции из
  встроенной сортировки, число результата в коробке) против 2 нс у Rust. На обычных объектах в
  d8 сортировка 980 строк каталога — 155 мкс из 206 мкс всего запроса.
