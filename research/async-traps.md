# Ловушки async + spawn + регионы

Каталог ошибок, на которые натыкается обычный код с `spawn`, каналами, `RwLock` и
регионами. Собран на четырёх программах в `playground/traps/`, каждая с вариантами:

| Программа | Что делает | Варианты |
|---|---|---|
| `pipeline.js` | конвейер на каналах: производитель, три считающие задачи, сборщик | `first`, `fixed`, `use-after-send`, `close-race`, `of-received` |
| `server.js` | запросы из канала, задача на каждый с `timeout()`, состояние в `RwLock` | `first`, `lock-await`, `half-write`, `abort-region`, `region-busy`, `check-then-use` |
| `cache.js` | замороженный кэш, задачи читают, главный поток перестраивает | `first`, `swap`, `borrow-await`, `channel-read`, `rwlock`, `rwlock-await` |
| `fanout.js` | отчёт по магазинам: задача на магазин, вложенные задачи по кварталам | `first`, `two-tasks`, `all-fail-fast`, `floating-child`, `joinset`, `plain-back`, `classes`, `forgot-await` |

Запуск: `playground/traps/run.sh <файл> <вариант> [секунды]` (d8 из `out/fast`, ограничение
времени через `alarm`). Все тексты ошибок ниже — настоящий вывод.

Слои, которые могут поймать ловушку:
- (a) структурный API `spawn.scope`: задачи не переживают блок, регионы возвращаются все
  разом, ошибка одной задачи отменяет остальные и закрывает каналы блока;
- (b) диагностика движка: где сейчас регион и кто его туда отправил, свои классы ошибок;
- (c) типы TypeScript;
- (d) ESLint с потоком управления через `await`;
- (e) изменение рантайма или API.

Тяжесть, по убыванию: порча данных > зависание > тихий неверный результат > поздняя
непонятная ошибка > понятная ошибка на месте.

## 1. Параллельный обход элементов одного региона

```js
const shops = new Region().run(() => [{ name: 'a', total: 0 }, { name: 'b', total: 0 }]);
await Promise.all(shops.map((shop) => spawn(summarize, shop)));
// внутри задачи то же самое: spawn по частям shop.months
```

- **Что происходит:** первый `spawn` увозит весь регион, второй бросает синхронно, прямо в
  `map`: `TypeError: OwnershipError: region 0 is being moved between isolates`. При двух
  отдельных вызовах текст другой: `TypeError: spawn() cannot move an argument: OwnershipError:
  region 0 is being moved between isolates`. Первая задача уже запущена, её отказ никто не
  ждёт: `2 pending unhandled Promise rejection(s) detected`, код выхода 1.
- **Где всплывает:** на той же строке, но текст не говорит, что регион уже отдан задаче и где
  она запущена.
- **Слой:** (b) — «регион 0 отдан задаче, запущенной в fanout.js:34»; (a)/(e) — явный способ
  разделить работу: копия на задачу, заморозка для чтения или разбиение региона.
- **Тяжесть:** понятная по месту, непонятная по смыслу. Самая частая первая ошибка: данные
  естественно лежат одним регионом.

## 2. Ошибка в одной стадии конвейера превращается в дедлок

```js
const pricers = [0, 1, 2].map(() => spawn(async (raw, priced) => {
  for await (const batch of raw) {
    for (const o of batch.orders) o.total = o.qty * o.price;  // новое поле
    await priced.send(batch);
  }
  priced.close();
}, raw, priced));
for await (const item of priced) { /* ... */ }
```

- **Что происходит:** все три задачи падают с `TypeError: Cannot add property total, region
  objects have a fixed shape`. Главный поток и производитель через 50 мс получают
  `DeadlockError: deadlock: every thread is waiting, and none of them can wake the others`.
  Настоящая причина видна, только если отдельно разобрать ручки задач.
- **Где всплывает:** в другом потоке, в виде другой ошибки.
- **Слой:** (a) — ошибка задачи отменяет блок, закрывает его каналы и всплывает первой;
  (b) — `DeadlockError` мог бы назвать последнюю упавшую задачу.
- **Тяжесть:** зависание, которое поиск дедлоков превращает в непонятную ошибку.

## 3. Кто закрывает общий выходной канал

```js
spawn(async (raw, out) => {
  for await (const x of raw) await out.send(x);
  out.close();                       // «я закончил — закрываю»
}, raw, out);                        // таких задач три
```

- **Что происходит:** первая закончившая задача закрывает канал, у двух других
  `TypeError: send on a closed channel`. Главный поток спокойно дочитывает и печатает итог по
  10 пачкам из 12.
- **Где всплывает:** нигде, если не проверять ручки задач.
- **Слой:** (e) — канал, который закрывается с последним отправителем, как в Rust; (a) — блок
  закрывает свои каналы сам.
- **Тяжесть:** тихий неверный результат, потеря данных.

## 4. Обычные объекты в задаче — копия

```js
const stats = { batches: 0 };
await Promise.all(workers.map(() => spawn((stats) => { stats.batches++; }, stats)));
print(stats.batches);                // 0
```

- **Что происходит:** изменения остаются в копии, ничего не сообщается. То же с массивом
  `report.done.push(i)`.
- **Где всплывает:** никогда.
- **Слой:** (d) — запись в захваченный или переданный обычный объект внутри колбэка `spawn`;
  (e) — отдавать задаче замороженную копию, чтобы запись бросала ошибку.
- **Тяжесть:** тихий неверный результат. Описано в документации, но первая попытка всегда
  такая.

## 5. Новое поле у объекта региона

```js
for (const order of batch.orders) order.total = order.qty * order.price;
```

- **Что происходит:** `TypeError: Cannot add property total, region objects have a fixed
  shape`.
- **Где всплывает:** на той же строке, но внутри задачи; вместе с п. 2 даёт дедлок.
- **Слой:** (c) — тип объекта региона без индексной сигнатуры; (d).
- **Тяжесть:** понятная ошибка на месте.

## 6. Использование после `send`

```js
const batch = new Region().run(() => makeBatch(b));
await raw.send(batch);
print('отправлена пачка', batch.batch);
```

- **Что происходит:** `TypeError: OwnershipError: region 3 is being moved between isolates`.
  Регион уже лежит в канале или у получателя, а не «переезжает». Задача-производитель падает,
  дальше — п. 2.
- **Где всплывает:** на следующей строке.
- **Слой:** (b) — «отправлен в канал в pipeline.js:25»; (d) — использование после `send`.
- **Тяжесть:** понятная по месту, вводящая в заблуждение по тексту.

## 7. Регион в задаче, а этот же поток трогает его из другого async-кода

```js
const bg = spawn(async (session) => { for (let i = 0; i < 5; i++) { session.hits++; await sleep(10); } }, session);
const onTick = async () => { await sleep(15); return session.hits; };
await onTick();
```

- **Что происходит:** `TypeError: OwnershipError: region 21 is owned by isolate 1, not by
  isolate 0`. Номера изолятов пользователю ничего не говорят. Так же ломаются:
  - забытый `await` у `spawn`;
  - чтение регионов после того, как `Promise.all` отказал на первой ошибке, а остальные задачи
    ещё идут. В `catch`, который печатает `shop.name`, ошибка бросается второй раз.
- **Где всплывает:** после `await`, в другой функции.
- **Слой:** (a) — до конца блока регион снаружи недоступен по построению, а блок дожидается
  всех задач; (b) — «регион 21 у задачи, запущенной в server.js:93, вернётся, когда она
  закончится»; (d).
- **Тяжесть:** поздняя непонятная ошибка.

## 8. `timeout()` и `abort()` не останавливают задачу, ждущую не канал и не лок

```js
const t = spawn(async (doc) => { doc.title = 'final'; await sleep(300); doc.words = 1000; }, doc)
    .timeout(20);
try { await t; } catch (e) { /* TimeoutError через 302 мс, а не через 20 */ }
print(JSON.stringify(doc));          // {"title":"final","words":1000}
```

- **Что происходит:**
  - `TimeoutError` приходит, только когда задача сама закончилась: через 302 мс вместо 20, и
    без регионов тоже через 300 мс;
  - все записи задачи на месте. В `server.js` (`half-write`) у задачи, отменённой по таймауту,
    в журнале есть и `start 0`, и `done 0`;
  - вызывающий считает запрос неудачным, а работа сделана: при повторе она применится дважды.
- **Где всплывает:** никогда (как ошибка), только задержкой.
- **Слой:** (e) — отказ ручки в срок хотя бы для задач без регионов; сигнал отмены, который
  видит обычный `await` (например, `spawn.signal`); (a).
- **Тяжесть:** тихая несогласованность.

## 9. `timeout()` у задачи, ждущей промис, который не выполнится

```js
const u = spawn(async () => { await new Promise(() => {}); }).timeout(20);
await u;                             // висит вечно
```

- **Что происходит:** процесс висит, поиск дедлоков этого не видит. Так же с
  `for (;;) await null`.
- **Где всплывает:** никогда.
- **Слой:** (e).
- **Тяжесть:** зависание.

## 10. Отмена посреди обновления: инварианты остаются сломанными

```js
{ using g = await state.write(); g.value.inFlight++; }
// работа; задачу отменяет timeout()
{ using g = await state.write(); g.value.inFlight--; g.value.served++; }
```

- **Что происходит:** после прогона 20 запросов `served 14 inFlight 4`: счётчик никогда не
  вернётся к нулю. Лок отпускается сам, «отравления» нет, никто не узнаёт, что данные
  наполовину обновлены.
- **Где всплывает:** никогда.
- **Слой:** (e) — отравление `RwLock`, если держатель упал или отменён; флаг «регион изменён
  отменённой задачей»; (a) — блок, который знает, что его задачи отменены.
- **Тяжесть:** порча данных (логическая).

## 11. Лок через `await`

```js
using g = await state.write();
g.value.inFlight++;
await sleep(req.cost);               // работа под локом
g.value.served++;
```

- **Что происходит:** все задачи встают в очередь за одним писателем. 20 из 20 запросов
  падают с `TimeoutError: spawn() task did not finish in 50 ms`, обслужен 1. Держатель лока
  при этом не отменяется (п. 8).
- **Где всплывает:** в других задачах, как таймауты.
- **Слой:** (d) — `await` при живом guard, как `await_holding_lock` в clippy; (b) —
  ожидание лока могло бы называть держателя.
- **Тяжесть:** деградация до зависания.

## 12. Ссылка, вынесенная из-под лока

```js
let prices;
{ using r = await lock.read(); prices = r.value.prices; }
await sleep(5);
return prices.sku1;
```

- **Что происходит:** `OwnershipError: region 1 is in an RwLock; use it through lock.read()
  or lock.write()`. Текст понятный.
- **Где всплывает:** после `await`.
- **Слой:** (d) — выход `guard.value` за блок; (c) частично.
- **Тяжесть:** поздняя, но понятная ошибка.

## 13. Билет задачи на замороженный регион берётся при старте, а не при `spawn()`

```js
spawn.poolSize = 1;
region.freeze();
const busy = spawn(() => { /* 50 мс счёта */ });
const queued = spawn((cfg) => cfg.limit, cfg);    // захватили замороженный cfg
region.thaw(); cfg.limit = 99; region.freeze();   // получилось: билета ещё нет
print(await queued);                              // 99
```

- **Что происходит:** `region.readers` сразу после `spawn` равен 0, и `thaw()` проходит.
  - Если задача стартует после повторной заморозки, она молча читает новое значение.
  - Если стартует посреди перестройки, падает. В `cache.js` (`first`) из 40 чтений 6 упали с
    `OwnershipError: region 0 is owned by isolate 0, not by isolate 2` и `OwnershipError:
    region 0 is frozen; borrow it to read it`.
- **Где всплывает:** в задаче, позже, или никогда.
- **Слой:** (e) — брать билет в момент `spawn()`; (b).
- **Тяжесть:** тихий неверный результат или поздняя непонятная ошибка.

## 14. `thaw()` при живых билетах: ждать нечем

```js
const handler = async () => { using b = region.borrow(); const p = cfg.x; await sleep(200); return p; };
handler();
region.thaw();       // Error: Region is still borrowed by 1 reader(s)
```

- **Что происходит:** синхронная ошибка, причём `Error`, а не `OwnershipError`. Ждать
  освобождения приходится циклом с повторами. Билет, который этот же поток держит через
  `await`, задерживает перестройку на всё ожидание (200 мс).
- **Где всплывает:** на месте.
- **Слой:** (e) — `await region.thawWhenFree()` или асинхронный `thaw`; (d) — билет через
  `await`.
- **Тяжесть:** понятная ошибка, но API толкает к циклу повторов.

## 15. Замороженный объект из канала без билета

```js
const reader = spawn(async (ch) => { const { value } = await ch.recv(); return value.prices.sku3; }, ch);
await ch.send(frozenCache);
```

- **Что происходит:** `TypeError: OwnershipError: region 0 is frozen; borrow it to read it`.
  Захваченный кэш читается без билета, пришедший через канал — нет, и текст не объясняет
  разницу.
- **Где всплывает:** на месте.
- **Слой:** (b) — подсказка «получен через канал: `Region.of(x).borrow()`»; (c).
- **Тяжесть:** понятная ошибка на месте.

## 16. Вложенный `spawn` без `await`

```js
spawn(async (own) => {
  spawn(async (own) => { await sleep(30); own.log.push('child'); }, own);  // без await
  own.log.push('parent');
}, own);
```

- **Что происходит:** родитель падает с `OwnershipError: region 1 is being moved between
  isolates`, запись ребёнка остаётся. Итог: `log: child`.
- **Где всплывает:** на следующей строке родителя.
- **Слой:** (a); (d) — `no-floating-spawn` должен видеть и вложенные вызовы; (b).
- **Тяжесть:** поздняя непонятная ошибка.

## 17. Отказ на первой ошибке оставляет «осиротевшие» задачи и необработанные отказы

```js
{
  using set = new JoinSet();
  for (const shop of own) set.spawn(summarize, shop);   // внутри Promise.all по вложенным задачам
  await set.next();
}                                                     // остальные отменяются
```

- **Что происходит:**
  - вложенные задачи из `Promise.all` внутри отменённых получают `AbortError: spawn() task was
    aborted with the task that spawned it`, но их уже никто не ждёт;
  - итог: `3 pending unhandled Promise rejection(s) detected`, код выхода 1;
  - то же с `task.then(...)` без `catch` в `server.js`: шесть `TimeoutError`;
  - стек всех таких ошибок указывает внутрь `spawn` (`at settle (<anonymous>:244:56)`), а не на
    место вызова.
- **Где всплывает:** при выходе из программы.
- **Слой:** (a) — блок владеет всеми ручками, необработанных отказов не бывает; (b) — стек
  места вызова `spawn` в ошибке задачи.
- **Тяжесть:** поздняя непонятная ошибка.

## 18. Что нельзя передать в задачу

```js
spawn((v) => v, new Date(0));   // и Map, Set, экземпляр класса, функция
```

- **Что происходит:** `TypeError: spawn() cannot send an argument: it contains a function, a
  class instance or another value that cannot be moved into a region`. Путь до значения
  (`arg.items[3].created`) не назван.
- **Где всплывает:** на месте.
- **Слой:** (c) — `RegionData` в типах `spawn` уже есть; (b) — путь в тексте.
- **Тяжесть:** понятная ошибка на месте.

## 19. Проверка, `await`, использование

```js
if (region.frozen) {
  await sleep(20);
  using b = region.borrow();
  return cfg.limit;                 // 20, хотя при проверке было 10
}
```

- **Что происходит:** ошибки нет, значение уже другое: за время `await` регион разморозили,
  изменили и заморозили. Гонки данных нет, логическая гонка есть.
- **Где всплывает:** никогда.
- **Слой:** (d).
- **Тяжесть:** тихий неверный результат (редкий).

## 20. Ошибки владения — `TypeError` с префиксом в тексте

- **Что происходит:**
  - `e.name` у всех ошибок владения — `TypeError`, поэтому журнал показывает
    `TypeError: OwnershipError: ...`, а `instanceof OwnershipError` невозможен;
  - ошибка `thaw()` при билетах — просто `Error`;
  - `AbortError`, `TimeoutError` и `DeadlockError` — `Error` с подменённым `name`, глобальных
    классов для `instanceof` нет;
  - разобрать ошибку программно можно только по тексту.
- **Слой:** (e) — настоящие классы: `OwnershipError` (наследник `TypeError` для
  совместимости) с полями `region`, `state` и `owner`, а также `AbortError`, `TimeoutError`,
  `DeadlockError`.
- **Тяжесть:** удобство; влияет на всё остальное.

## Попутно найдено

- **Ошибка пула d8 при выходе.** Если программа завершается вскоре после запуска двух и
  больше задач, каждый ещё стартующий воркер пула печатает
  `unnamed:129: ReferenceError: spawn is not defined` (на строке `spawn.aborted = () => {`).
  - Воспроизводится стабильно: `await Promise.all([0, 1].map((i) => spawn((i) => i, i)))` и
    конец файла.
  - С паузой в 300 мс перед выходом ошибки нет.
  - Эта строка попала в сохранённый вывод примеров документации
    `docs/examples/30-channel-pipeline.out.txt` и `38-rwlock.out.txt`.
- Падений d8 (CHECK, segfault) не было. Зависания — только п. 9.
- **Исправлено:** ошибка пула при выходе. Воркер пула ставит `spawn.aborted`, только если
  `spawn` уже есть.
