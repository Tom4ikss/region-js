Глава 7

Редактор и линтеры

Большую часть ошибок с регионами и spawn d8 покажет только при запуске. Часть из них можно увидеть раньше, прямо в редакторе. Для этого есть песочница playground/: типы, правила Biome и небольшой плагин ESLint. На этой странице — что ловит каждый из них и как их подключить.

Кто что ловит

Проверок три слоя, и у каждого свои возможности. Типы знают, что можно положить в регион и какие у него методы. Biome находит шаблоны в коде, например class внутри колбэка spawn. ESLint умеет следить за порядком выполнения: что задача запущена, а регион трогают до её конца. Остальное видно только при запуске.

Как подключить

  1. Откройте папку playground в VS Code целиком (File → Open Folder). Типы и правила подключаются из её настроек, отдельный файл они не увидят.
  2. Выполните npm install: он ставит Biome, ESLint и TypeScript.
  3. Поставьте расширения Biome и ESLint. VS Code сам предложит их, они записаны в .vscode/extensions.json.
  4. Укажите путь к своему d8 в .vscode/settings.json, настройка regions.d8Path. Тогда Cmd+Shift+B запускает открытый файл командой d8 --harmony-regions --module --expose-gc --max-serializer-memory=4000 файл.js.

То же можно проверить из терминала, в папке песочницы:

$ npm run typecheck      # типы, tsc
$ npm run lint           # правила Biome
$ npm run lint:regions   # правила ESLint для папки examples
$ npm run test:rules     # тесты самих правил ESLint

В examples/mistakes.js собраны типичные ошибки, и каждая должна подсветиться. Если подсветки нет, начните с этого файла.

Если поменяли плагин

Сервер ESLint в VS Code загружает плагин один раз. После правки файлов в eslint-plugin-regions/ перезапустите его: палитра команд → «ESLint: Restart ESLint Server». Иначе редактор будет показывать старые сообщения или не покажет новые.

Типы

Файл types/regions.d.ts описывает Region, spawn, Channel и глобальные функции d8 (print, Worker с его getMessage). Встроенный в VS Code TypeScript читает его через jsconfig.json, ставить ничего не нужно. Это даёт автодополнение и проверку того, что кладётся в регион: результат run и аргументы spawn должны быть данными (примитивы, простые объекты, массивы, типизированные массивы).

error TS2322: Type 'Map<any, any>' is not assignable to type 'RegionData'.
error TS2551: Property 'frezee' does not exist on type 'Region'. Did you mean 'freeze'?
error TS2339: Property 'total' does not exist on type '{ count: number; }'.

Последняя ошибка — та же фиксированная форма, что и в d8 (чтение и запись): тип результата run знает только поля, которые были при создании.

Чего типы не знают. Типизированный массив поверх SharedArrayBuffer для них такой же, как любой другой, а d8 его отклонит. Что можно отправить в канал, типы не проверяют: у Channel без параметра тип значения any.

Biome

Правила Biome лежат в rules/*.grit и подключены в biome.json. Они ищут шаблоны в коде и не следят за порядком выполнения. Четыре правила повторяют проверки, которые spawn делает при вызове, только раньше, в редакторе.

× spawn() callbacks cannot declare classes: their methods cannot be checked and sent to the worker. Use plain objects and functions.
× spawn() callbacks cannot use eval or with: the variables they need cannot be known in advance.
× spawn() needs an arrow function or a function expression; methods cannot be sent to a worker. Wrap it: spawn(() => ...).
! join() blocks this thread until the task ends; on the main thread prefer `await spawn(...)`.

Правило про join() срабатывает только на цепочку spawn(...).join() и не знает, в каком потоке код. В воркере или в коротком скрипте d8 join() уместен, и предупреждение можно игнорировать. Почему в главном потоке лучше await, показано в практике 7.

ESLint

Плагин eslint-plugin-regions/ подключён в eslint.config.mjs набором recommended. В нём три правила. ESLint видит области видимости переменных и порядок выражений, поэтому может сказать «регион уехал в задачу на строке 3, а на строке 4 его читают».

regions/no-floating-spawn

Ручку задачи никто не ждёт: ни await, ни join(), ни возврата из функции. Результат и ошибка такой задачи теряются (ошибку d8 всё же покажет, см. «Ошибки не теряются»). Это предупреждение, а не ошибка.

warning  The result of spawn() is neither awaited nor joined, so its value and errors are lost. Use `await spawn(...)`, `.join()`, return the handle, e.g. to Promise.all(), or start the task with `s.spawn(...)` in `spawn.scope(async (s) => ...)`, which waits for it
warning  This callback returns `i`, not the handle of this spawn(), so whoever waits for the callback (e.g. Promise.all over map()) does not wait for the task. Return the handle: `return spawn(...)`, or `return spawn(...).then(() => i)` to keep the value

Второй случай — колбэк map, который запускает задачу, но возвращает другое значение. Promise.all тогда ждёт это значение, а не задачу (практика 10). Задачи, запущенные внутри другой задачи без await, правило тоже отметит, хотя внешняя задача их дождётся (задачи внутри задач).

regions/no-region-use-while-spawned

Регион, захваченный задачей или переданный ей аргументом, уезжает в воркер и возвращается, когда задача закончилась. Задачи s.spawn() из spawn.scope и set.spawn() из JoinSet правило считает так же. Правило находит три ошибки вокруг этого. Все три в d8 закончились бы OwnershipError.

error  'cart' was moved into the spawn() task on line 3 and comes back only when it finishes: using it here throws OwnershipError. Wait for the task first (await it or call join())
error  This spawn() runs repeatedly and every task wants to move 'counter': only the first one gets it, the next ones throw OwnershipError. Await each task, freeze the region to share it read-only, or give every task its own data
error  'config' is in a frozen region: tasks can read it but writing throws OwnershipError. Thaw it first, or let one task own it instead of freezing

Правило понимает, что задача закончилась, если её ждут через await (в том числе в Promise.all) или join(), и что замороженный регион не уезжает, а становится общим. Заморозку оно отслеживает по вызовам freeze() и thaw() до spawn.

Анализ простой, и у него есть границы. Регионом правило считает переменную, созданную через что-то.run(...). Объекты региона, полученные иначе (результат задачи, поле другого объекта, литерал #{}), оно не отслеживает. С опцией checkAllCaptures оно проверяет все захваченные переменные, но тогда будет ругаться и на обычные данные, которые просто копируются. Обращения из колбэков, которые выполнятся позже (таймеры, обработчики), правило не отмечает: оно не знает, закончится ли задача к тому времени.

regions/no-floating-borrow-while

borrowWhile с асинхронной функцией держит билет, пока не выполнится её промис. Если этот промис не вернуть из задачи и не дождаться, задача закончится раньше, и билет сдадут посреди работы (подробнее).

error  borrowWhile() returns a promise here and nobody waits for it: a spawn() task ends without waiting, and its borrow is released before this work is done. Return or await it

Голый borrow() с отложенным чтением правило не видит. Такой билет d8 сдаёт в конце задачи сам и печатает предупреждение в воркере.

Литералы #{} в редакторе

Синтаксиса #{...} и #[...] (литералы регионов) нет в JavaScript, поэтому сами по себе инструменты его не знают. Для VS Code в playground/vscode-region-literals лежит расширение. Оно подсвечивает # как оператор и подключает к TypeScript плагин: тот заменяет # перед { и [ пробелом до разбора файла. Длина текста не меняется, поэтому ошибки, подсказки и автодополнение стоят на своих местах, а литерал получает тип такого же обычного литерала. Ставится оно символической ссылкой (команда в README расширения), после чего нужен «Developer: Reload Window».

Одна особенность от самого TypeScript: пустой #[] для него — пустой [], то есть never[], и push в него подсвечивается как ошибка. Подскажите тип: /** @type {Order[]} */ (#[]).

Biome и ESLint литералы не разбирают. В playground/ файлы с литералами лежат в experimental/, который оба пропускают, а TypeScript проверяет. Запускайте их в d8 с флагом --harmony-regions.

Без всего этого обходится директива 'use region' (подробнее): с ней обычные {} и [] в функции создаются как #{} и #[], а для инструментов это обычный JavaScript со строкой-директивой.

Что видно только при запуске

Некоторые ошибки нельзя найти, не выполняя код:

  • захваченная переменная, в которой лежит Map, функция или экземпляр класса: типы проверяют аргументы spawn, но не захваты. Сюда же захваченный this с методами (this и arguments);
  • переменная, захваченная до инициализации, и одно имя с разными значениями в разных функциях (что spawn отклоняет сразу);
  • обращение к региону, которым сейчас владеет другой поток, если регион пришёл не из run в этой же функции;
  • чтение замороженного региона без билета, например объекта, который пришёл через postMessage или канал;
  • голый borrow(), переживший задачу, и view типизированного массива, прочитанный до переезда или заморозки.

Линтер здесь только помогает. Защищает от гонок данных сам движок: он проверяет владельца при каждом обращении, сработало правило в редакторе или нет.
