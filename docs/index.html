Эксперимент с движком V8

Регионы владения: объекты, которые переезжают между потоками без копирования

Это исследовательский форк V8. В нём обычные объекты и массивы можно сложить в «регион» и отдать воркеру за доли миллисекунды, сколько бы данных там ни было. Взамен у региона в каждый момент только один хозяин, и движок проверяет это при каждом обращении.

Сразу о границах

Всё это работает только в d8, тестовой оболочке V8. В браузере и в Node этого нет. Это прототип: его задача — проверить, можно ли так сделать вообще и сколько это стоит. Подробно об ограничениях — на последней странице.

Пример: дерево из 131 тысячи узлов

Возьмём обычное дерево объектов и отправим его в воркер двумя способами. Сначала как сегодня: postMessage копирует всё дерево. Потом через регион: дерево лежит в общей памяти, и воркеру передаётся право им пользоваться.

Копия заняла больше сотни миллисекунд, переезд — сотые доли миллисекунды. И время переезда почти не растёт с размером: для дерева из миллиона узлов оно около 0,12 мс, а копия такого дерева идёт почти секунду.

Посмотрите на последнюю строку. После переезда главный поток больше не может читать дерево, и движок выдаёт OwnershipError. Так и задумано: данные никто не копировал, и два потока не должны трогать их одновременно. Владелец один, и проверяет это сам движок, а не договорённость в команде.

Главные цифры

Переезд дерева из 1 млн узлов0,12 мскопия через postMessage — 928 мс
Чтение одного дерева в 8 потоках×5,9быстрее одного потока; быстрых ядер 6
Объект в воркер и обратно≈11 мксвозвращается тот же самый объект
Запуск задачи spawn≈3 мкспул воркеров; без пула было ≈2,5 мс

Цифры сняты на сборке с включёнными внутренними проверками, на Apple Silicon. Абсолютные значения на другой машине будут другими, смотреть стоит на соотношения. Подробности и графики — на странице «Цифры». Там же честно сказано, что пока медленнее обычного JS: запись в поля объектов региона дольше примерно в 1,7 раза, доступ к массиву региона по индексу — примерно в 3,3 раза.

Что умеет прототип

  • Регион (new Region(), region.run(fn)) — группа обычных объектов, массивов, строк, чисел и типизированных массивов в общей памяти. Читать и писать может только владелец. Данные попадают в регион копией готового графа через run или по ходу работы: Region.object() и Region.array() внутри region.enter(), а под флагом --harmony-region-literals — литералами #{...} и #[...], которые создают объект сразу в регионе, без копии. Массивы региона растут через push, у объектов набор полей фиксирован.
  • Переезд (worker.postMessage(msg, [region])) — отдать регион другому потоку без копирования. Отправитель теряет доступ. spawn и каналы перемещают регионы сами, без списка transfer.
  • Заморозка (region.freeze(), region.borrow()) — регион только для чтения, зато его могут читать все потоки сразу, взяв билет borrow(). Разморозить может тот, кто заморозил, и это право можно передать.
  • spawn(fn) — запустить функцию в отдельном потоке одной строкой. Задачи идут в пул долгоживущих воркеров. Нужные функции переменные spawn находит сам, результат возвращается через регион. Ручку задачи ждут как промис, вложенные задачи заканчиваются раньше внешней, ошибки не теряются.
  • Каналы (new Channel(), send, recv, select) — очереди между потоками, как в Go. Регион, отправленный в канал, переезжает без копии.
  • RwLock (new RwLock(data), await lock.write(), await lock.read()) — общие данные, которые потоки пишут по очереди или читают вместе. Ссылка, сохранённая после отпуска лока, перестаёт работать (подробнее).
  • Освобождение (region.free(), using) — отдать регион сразу, не дожидаясь сборщика мусора. После этого его объекты недоступны никому (подробнее).
  • Песочница для редактора — типы и правила Biome и ESLint, которые подсвечивают типичные ошибки до запуска.
