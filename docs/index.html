An experiment with the V8 engine

Parallel JavaScript without copies

This is a research fork of V8. spawn(fn) runs a function on another thread in one line. Objects created under the 'use region' directive or with #{} literals live in shared memory from the start and pass between threads without copying, however many there are. In exchange, data has exactly one owner at any moment, and the engine checks this on every access. There are no data races.

Limits up front

All of this works only in d8, the V8 test shell. It is not available in browsers or Node. This is a prototype: its job is to find out whether this can be done at all and what it costs. The limits are covered in detail on the last page.

Example: orders on four threads

Four spawn tasks build 25,000 orders each. Because of 'use region', every {} and [] in the function is created directly in shared memory, in the task's region. The returned array moves to the main thread together with the region; nothing is copied. For comparison, plain workers do the same work: postMessage copies every order back.

The difference is more than an order of magnitude, and it grows with the data: a copy costs in proportion to the number of objects, and moving a region does not. A tree of a million nodes moves in 0.12 ms, while copying the same tree through postMessage takes almost a second (measurement).

The task code is ordinary JavaScript. 'use region' is a directive string, like 'use strict', so TypeScript, ESLint, and Biome read this code without extensions. spawn finds the variables a task needs and passes them on its own.

Versus tokio and plain workers

Three realistic scenarios with orders, each done three ways: spawn with regions, plain workers with postMessage (how it is done in JS today), and Rust with tokio. Each uses four worker threads. V8 here is built without internal checks, like tokio in release mode (tests/bench-real.js and tests/tokio-bench, best of five runs).

Scenariospawn + regionsworkers + postMessagetokio
Build 200,000 orders on four threads and read them on the main thread38 ms220 ms16.5 ms
200 batches of 1000 orders: hand them to threads, compute a discount, return13 ms309 ms0.7 ms
A catalog of 100,000 products: share it with four threads, a million reads on each17 ms59 ms1.6 ms

Against today's workers, regions win by 3.5 to 23 times: the data is not copied in either direction. tokio is still far ahead, by 2 to 19 times. Rust reads a struct field in one instruction, while we check the object's shape and owner. A tokio task is a state machine in the memory of the same thread, while a spawn task is a message to another V8 isolate. We come closest where a lot is created: strings and heap objects are expensive in Rust too. A per-scenario breakdown and a thousand empty tasks against tokio are on the Numbers page.

That page also states plainly what is still slower than ordinary JS: writing to fields of region objects takes about 1.7 times longer, and indexed access to a region array about 2 times longer.

What the prototype can do

  • spawn(fn, ...args): a function on a separate thread in one line. Tasks go to a pool of long-lived workers, spawn finds the variables it needs on its own, and regions move there and back without a copy. A task handle is awaited like a promise. Nested tasks finish before the outer one, errors are not lost, and there is cancellation: abort, timeout, JoinSet (more).
  • Data in shared memory from the start: 'use region' at the top of a function or file makes every {} and [] a region object, and the #{...} and #[...] literals do the same in specific places. The object is created directly in machine code, with no intermediate copy (more).
  • Channels (new Channel(), send, recv, select): queues between threads, as in Go. A region sent into a channel moves without a copy. If all threads are waiting on each other, the waits end with a DeadlockError (more).
  • RwLock (new RwLock(data), await lock.write(), await lock.read()): shared data that threads write one at a time or read together (more).
  • Shared read-only data: Region.share(data), like Arc<T> in Rust: all threads read the same objects without copies and without locks (more). There is also temporary freezing with the right to thaw: freeze(), borrow(), thaw() (more).
  • Region: a group of ordinary objects, arrays, strings, numbers, and typed arrays in shared memory with one owner. Besides literals, data gets into it as a copy of an existing graph through region.run(fn). Arrays grow with push; objects have a fixed set of fields. A region stores functions without a closure through Region.fn, and objects of its own thread through LocalRef handles (Region.localRef) (more).
  • Workers directly: worker.postMessage(msg, [region]) hands a region to a worker without a copy. This is the low level: spawn and channels do the same thing on their own (more).
  • Freeing (region.free(), using): release a region right away, without waiting for the garbage collector (more).
  • An editor playground: types and Biome and ESLint rules that highlight common mistakes before you run the code.
