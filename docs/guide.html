Глава 3

API шаг за шагом

Здесь всё, что есть в прототипе, кроме spawn и каналов: им отданы отдельные страницы, про spawn и про каналы. Каждый пример — файл из папки examples/, запущенный в собранном d8. Под кодом — его настоящий вывод.

Как читать примеры

Примеры запускаются так: d8 --harmony-regions файл.js (полная команда — на странице «Ограничения и планы»). Вместо console.log в d8 используется print. Строку-предупреждение «V8 is running with experimental features enabled», которую d8 печатает первой, мы из вывода убрали.

Некоторые примеры запускаются с флагом --module, чтобы писать await прямо на верхнем уровне файла. Такие файлы начинаются со строки // d8-flags: --module.

Ещё одна особенность d8: worker.getMessage() останавливает поток, пока не придёт ответ от воркера. Так короче писать примеры. В браузере то же самое делается через worker.onmessage или промис, который ждут через await.

1. Создать регион

new Region() создаёт пустой регион, владелец — текущий поток. Положить в него данные можно через region.run(fn): функция выполняется как обычно, а то, что она вернула, копируется в регион вместе со всем, на что ссылается. run возвращает уже копию, которая лежит в регионе. Второй способ — создавать объекты сразу в регионе через Region.object() и Region.array(), о нём раздел 11.

Копирование внутрь происходит один раз, при создании. Дальше объекты можно передавать сколько угодно раз без копий. region.id — номер региона, region.owner — номер потока-владельца (в терминах V8 — isolate; у главного потока номер 0). Номера освободившихся регионов движок раздаёт заново, так что id уникален только среди живых регионов.

Важно

Объекты, которые вы создали внутри fn, и объекты в регионе — разные. Если внутри функции вы сохранили ссылку на свой объект где-то снаружи, она будет указывать на обычный объект, а не на копию в регионе. Работайте с тем, что вернул run.

2. Чтение и запись

Владелец читает и пишет поля как обычно. Но есть три правила:

  • в поле можно записать число, строку, true/false, null, undefined или объект из того же региона;
  • обычный объект из своего потока записать нельзя: он живёт вне региона, и другой поток не смог бы его прочитать. Исключение — типизированный массив: он копируется в регион (раздел 9);
  • набор полей у объекта фиксирован: добавить новое свойство нельзя. Отсутствующее поле читается как undefined. Массивы при этом растут и укорачиваются (раздел 3).

Циклы и общие куски графа при копировании сохраняются: если два поля указывали на один объект, в регионе они тоже указывают на одну копию.

Почему форма фиксирована

Регион — как квартира с уже расставленной мебелью. Переставлять вещи внутри (менять значения полей) можно, а пристраивать новую комнату (добавлять свойство) нельзя. Благодаря этому другой поток, получив регион, видит объекты точно такой формы, какой их создали, и движку не нужно согласовывать изменения структуры между потоками.

3. Массивы и методы

У объектов региона нет своего прототипа. Когда вы обращаетесь к полю, которого нет в самом объекте, движок ищет его в Array.prototype или Object.prototype того потока, который сейчас читает. Поэтому работают for...of, spread, map, filter, slice, includes и другие методы массивов. Массивы региона растут и укорачиваются: push, pop, splice, запись за концом и length = n работают. Лишнее место под элементы массив держит про запас, как обычный массив JS, так что серия push не копирует его каждый раз. Форма объектов, наоборот, фиксирована: новое поле у объекта региона добавить нельзя.

Перечисление ключей тоже работает как у обычных объектов: Object.keys, Object.values, Object.entries, for...in, JSON.stringify (массив региона превращается в JSON-массив), Array.isArray, flat, spread объекта { ...obj } и деструктуризация. Spread даёт обычный объект, в который уже можно добавлять поля. Копия при этом поверхностная: вложенные объекты остаются в регионе.

Для потока, который не владеет регионом, всё это бросает OwnershipError, как и обычное чтение поля (пример в разделе 5).

Про скорость

Методы из Array.prototype (map, filter, Array.from, spread массива, for...of) на массиве региона пока заметно медленнее простого цикла for по индексу. Цифры — на странице «Как делать и как не делать».

4. Что нельзя положить в регион

В регион попадают только простые объекты (их прототип — Object.prototype или null), обычные массивы, типизированные массивы и примитивы. Функции, Map, Set, Date, BigInt, Symbol, сам ArrayBuffer, DataView, экземпляры классов, наследники Array и объекты из другого региона вызовут ошибку. Типизированным массивам отдан раздел 9.

Экземпляр класса раньше молча копировался как обычный объект и терял класс. Теперь это ошибка: у объекта в регионе нет своего прототипа, поэтому методы класса до него всё равно бы не дошли. Если нужны данные из экземпляра, переложите их в простой объект: region.run(() => ({ x: point.x })).

5. Переезд в воркер

Чтобы передать регион воркеру, отправьте его объекты через postMessage и укажите сам регион в списке transfer. Воркер получит те же объекты, а не копию, и станет их владельцем. Главный поток доступ потеряет.

Видно два разных текста ошибки. Сразу после отправки регион ещё в пути: «is being moved between isolates». Когда воркер получил сообщение, владелец уже он: «is owned by isolate 1, not by isolate 0». Object.keys, JSON.stringify и прочее перечисление ключей проверяют владельца так же, как чтение поля.

Сам объект region в данные сообщения класть не нужно, достаточно объектов из него. Объекты региона всегда передаются по ссылке. Если отправить их без списка transfer, воркер получит ссылку, но прочитать по ней ничего не сможет, пока регион к нему не переедет: владелец остаётся прежним.

В списке transfer можно указать и сам объект региона, он означает свой регион: worker.postMessage(order, [order]) работает так же, как [region] или [Region.of(order)].

postMessage со списком transfer — самый низкий уровень, на нём построено всё остальное. Обычно удобнее spawn и каналы: они перемещают регионы сами, без списка transfer, а spawn к тому же идёт мимо postMessage, через свою очередь, и обходится дешевле.

6. Вернуть регион обратно: Region.of

В воркере нет переменной region, есть только полученные объекты. Region.of(obj) находит регион по любому его объекту. С ним воркер может вернуть данные тем же способом. Для списка transfer хватит и самого объекта (раздел 5), а Region.of нужен, чтобы вызвать методы региона: borrow(), freeze(), free(). Проверить, лежит ли значение в регионе, не ловя ошибку, можно через Region.isRegionObject(value).

Тысяча кругов «туда и обратно», и в конце в руках тот же самый объект: current === state. Один круг — два переезда и две пересылки сообщения — занимает около 10–11 микросекунд, от запуска к запуску по-разному.

7. Заморозка и рассылка

region.freeze() делает регион доступным только для чтения, причём всем потокам, но читают его под билетом borrow() (раздел 8). Замороженный регион отправляют без списка transfer: каждый получатель видит те же объекты. Без билета чтение у получателя бросает OwnershipError, это видно в выводе воркера 0. region.frozen показывает, заморожен ли регион. region.thaw() возвращает владельцу право писать.

Кто может разморозить

Разморозить регион может только тот поток, который его заморозил. Остальные получат ошибку «Region is not frozen by this isolate», даже если читают регион. Есть ли это право у текущего потока, показывает region.frozenHere.

Право можно передать. Если положить замороженный регион в список transfer, данные никуда не едут (они и так общие), а получатель получает право разморозить. Отправитель его теряет и дальше читает регион, как все остальные, под билетом.

Отдать право может только тот, у кого оно есть: если другой поток положит регион в transfer list, будет ошибка «Region was frozen by another isolate». Задача spawn, которая заморозила регион, возвращает право вызывающему вместе с результатом (пример на странице про spawn).

8. Билеты читателя: borrow

region.borrow() выдаёт билет и увеличивает счётчик region.readers. Пока есть хотя бы один билет, thaw() не сработает. ticket.release() сдаёт билет. Если объявить билет через using, он сдастся сам при выходе из блока, даже если внутри случилось исключение.

Брать билет можно в любом потоке, в том числе в воркере: Region.of(obj).borrow(). Без билета замороженный регион читают только тот поток, который его заморозил (или получил право разморозить), и задачи spawn, которые захватили регион или получили его аргументом: им билет выдаётся сам, на всё время задачи (подробнее). Остальные получают OwnershipError: region N is frozen; borrow it to read it, и на обычных полях, и на типизированных массивах. Это касается и объекта, который пришёл через postMessage или канал.

Зато пока билет у вас, thaw() не пройдёт: он бросит «Region is still borrowed by N reader(s)». Поэтому читатель никогда не увидит разморозку посреди чтения и не прочитает устаревшее значение.

region.borrowWhile(fn) берёт билет, вызывает fn и сдаёт билет, когда fn закончилась. Если fn вернула промис, билет сдаётся, когда промис выполнится или отклонится. borrowWhile возвращает то, что вернула fn (для асинхронной функции — промис с её результатом). Внутри задач spawn для асинхронной работы нужен именно он, потому что обычный билет живёт не дольше задачи (подробнее на странице про spawn).

9. Типизированные массивы

В регион можно положить Uint8Array, Float64Array и остальные типизированные массивы, включая BigInt64Array и Float16Array. Они устроены иначе, чем объекты региона: регион хранит сам блок памяти, а при чтении поля вы получаете обычный локальный типизированный массив, который смотрит на эту память (view). Поэтому работа с ним идёт на полной скорости, как с любым типизированным массивом, без проверки владельца на каждом элементе.

  • По умолчанию массив копируется в регион, исходный остаётся у вас и с регионом не связан. Если массив был частью большого буфера (subarray), копируются только его байты.
  • Без копии — через второй аргумент run: region.run(fn, [buffer]). Память массивов, чей ArrayBuffer есть в этом списке, переезжает в регион, а исходный буфер отсоединяется, как после transfer в postMessage: его длина становится 0.
  • Каждое чтение поля даёт новый view: state.pixels === state.pixels — false, но байты те же. Сохранить view в переменную перед циклом можно и нужно.
  • Записать в поле новый типизированный массив можно, даже другой длины: он копируется, как в run.
  • Нельзя: массивы поверх SharedArrayBuffer и буферов с изменяемым размером, сам ArrayBuffer и DataView.

Когда view отсоединяются

Пока регион у вас, view над его памятью работают как обычно. Когда регион уезжает в другой поток или замораживается, все view владельца отсоединяются: длина становится 0, элементы читаются как undefined. Так же ведёт себя ArrayBuffer после transfer. Ошибки OwnershipError здесь нет, потому что проверки владельца на каждом элементе нет. После возврата региона старые view так и остаются пустыми: прочитайте поле заново и получите новый.

Читатели замороженного региона получают view только для чтения. Запись в него вне strict mode молча не проходит, в strict mode и у методов вроде fill и set бросает TypeError.

View замороженного региона получают те же потоки, что могут читать его поля: тот, кто его заморозил, и тот, кто держит билет borrow(). Но у view есть своё правило. Обычное поле проверяется при каждом чтении, а view читает память напрямую. Если бы view жил дольше права читать, поток видел бы регион и после разморозки, когда в него уже пишет новый владелец. Поэтому, когда поток сдаёт последний билет, его view отсоединяются. View того, кто заморозил, отсоединяются при thaw() или когда он передаёт право разморозки. Внутри spawn билет на замороженные регионы задача берёт сама, на всё время работы (подробнее).

Отсюда правило: не держите view дольше, чем нужно. Прочитали поле, поработали, отпустили. После await задачи, переезда или freeze читайте поле заново. Почему для больших массивов чисел это ещё и быстрее, показано в практике 9.

10. Освободить регион: free

Обычно память регионов, как и любых объектов JS, освобождает сборщик мусора: когда на объекты не осталось ссылок, они исчезают. Но иногда ссылки остаются там, где их не ждёшь: в кэше, в замыкании, в забытой переменной. Тогда большие данные висят в памяти, пока на них кто-то смотрит.

region.free() отдаёт регион сразу, не дожидаясь, пока пропадут ссылки. После этого любое обращение к его объектам бросает OwnershipError: region N was freed, из любого потока и из любого кода, в том числе из уже скомпилированного. Память типизированных массивов освобождается в момент вызова, а view владельца отсоединяются. Сами объекты опустошаются при ближайшей сборке общей кучи: всё, что они держали, уходит, даже если на них ещё есть ссылки. В C такая операция оставила бы висячий указатель, а здесь она безопасна: доступ к региону и так проверяется при каждом обращении, а освобождённый регион — просто ещё одно его состояние.

Освободить можно только свой регион. Замороженный регион освобождает тот, кто его заморозил, и только когда не осталось билетов, как при thaw(). Регион в пути или чужой освободить нельзя. Объявленный через using, регион освобождается в конце блока. Если к этому времени он уехал в другой поток, using ничего не делает: уехавшее значение не освобождают, как в Rust.

region.byteSize показывает, сколько байт региону досталось при копировании: объекты, их массивы, строки и память типизированных массивов. Это приблизительная цифра: объекты из Region.object() и Region.array() и рост массивов в неё входят, а строки, записанные в поля позже, нет. Region.stats() показывает, сколько регионов живо, сколько освобождено, но ещё не собрано, и сколько байт держат живые.

11. Писать прямо в регион

region.run(fn) удобен, когда данные уже есть или их проще собрать обычным кодом: всё, что вернёт fn, копируется в регион одним махом. Но иногда хочется складывать данные в регион по ходу работы, не собирая сначала копию. Для этого регион делают текущим через region.enter(), а объекты создают прямо в нём: Region.object({...}) и Region.array(...).

enter() возвращает скоуп: объявленный через using, он заканчивается вместе с блоком, и текущим снова становится предыдущий регион. Внутри run(fn) регион тоже текущий. Без текущего региона Region.object() бросает ошибку. У самого региона те же методы есть и без enter: region.object(...) и region.array(...). В задаче spawn текущего региона нет, ведь туда может приехать несколько регионов сразу. Там удобнее Region.of(obj).object(...).

Обычный объект в поле региона по-прежнему не кладётся: регион хранит только свои объекты. Ошибка подскажет обернуть значение в Region.object(). Сам литерал {...} при этом всё ещё создаётся в памяти потока и копируется в регион по быстрому пути. Объекты, которые уже лежат в регионе, заново не копируются. Поэтому, если вложенные значения уже созданы через Region.object() и Region.array(), копируется только сам литерал. Обычные объекты внутри литерала копируются вместе с ним. Создавать объекты прямо в общей памяти, вообще без копии, умеют литералы #{} и #[] (раздел 12).

Для больших объёмов этот способ медленнее run. Каждый вызов Region.object() — отдельная копия, и 200 000 объектов, созданных по одному, создаются в 2,4 раза дольше, чем через один run: 475 мс против 198. Читаются они потом так же быстро, потому что объекты с одинаковыми ключами получают одну форму, как бы их ни создали (практика 12). Поэтому Region.object() хорош, чтобы добавлять данные в регион по ходу работы. Большой набор, который известен сразу, быстрее собрать обычными объектами и скопировать одним run.

12. Литералы #{} и #[]

Region.object({...}) всё ещё создаёт литерал в куче потока и копирует его в регион. Литералы #{...} и #[...] создают объект или массив сразу в текущем регионе, без промежуточного объекта и без копии. Они включаются отдельным флагом --harmony-region-literals, который сам включает и --harmony-regions. Без флага #{ — синтаксическая ошибка. Пример ниже запущен с этим флагом.

Текущий регион нужен так же, как для Region.object(): литерал работает внутри enter() или run(). В задаче spawn текущего региона нет, туда входят явно: using _ = Region.of(x).enter().

  • Ключи — имена, строки в кавычках и короткая запись #{ id }.
  • Значения — примитивы, объекты того же региона (в том числе другие #{} и #[]) и типизированные массивы, которые копируются. Литерал ничего не копирует за вас, поэтому обычный {} или [] внутри него — ошибка: вложенные объекты тоже пишутся как #{}, массивы — как #[]. Объект другого региона внутри даёт OwnershipError, как при записи в поле.
  • Нельзя: spread, дырки в массиве, методы и вычисляемые ключи. Это синтаксическая ошибка.
  • Форма объекта фиксирована, как у любого объекта региона. Массив растёт через push.

Цена сегодня — вызов рантайма на каждый литерал: около 0,5 мкс на #{} с двумя полями и около 0,3 мкс на #[]. Быстрого пути в машинном коде, как у обычных литералов, пока нет, это следующий шаг. 200 000 товаров литералами и push создаются за 253 мс: быстрее, чем через Region.object() (479 мс), но дольше одного run (194 мс). Сам push в массив региона идёт без рантайма, около 25 нс на элемент. Замер — на странице «Цифры».

TypeScript, Biome и ESLint синтаксис #{} пока не понимают (подробнее).

Всё API на одной странице

ЧтоЧто делает
new Region()Пустой регион, владелец — текущий поток.
region.run(fn)Вызывает fn, копирует результат в регион и возвращает копию.
region.run(fn, [buffer])То же, но память типизированных массивов с этими ArrayBuffer переезжает без копии, а исходные буферы отсоединяются.
region.id, region.ownerНомер региона и номер потока-владельца.
Region.of(obj)Регион, в котором лежит obj. Для обычного объекта — ошибка.
Region.isRegionObject(value)Лежит ли значение в каком-нибудь регионе. Ошибок не бросает.
worker.postMessage(msg, [region])Переезд: получатель становится владельцем, отправитель теряет доступ. Вместо region можно указать любой его объект.
worker.postMessage(msg)Для объектов замороженного региона — рассылка без копии.
worker.postMessage(msg, [frozenRegion])Для замороженного региона — передать право разморозить.
region.freeze(), region.thaw()Заморозить (читают все под билетом, не пишет никто) и разморозить (только тот, кто заморозил или получил право, и только без читателей).
region.frozen, region.readersЗаморожен ли регион и сколько билетов сейчас выдано.
region.frozenHereЕсть ли у текущего потока право разморозить регион.
region.borrow()Билет читателя: без него замороженный регион читает только тот, кто его заморозил, и задачи spawn, которым он достался. У билета есть release(), и его можно объявить через using.
region.borrowWhile(fn)Держит билет, пока выполняется fn или пока не выполнится её промис. Возвращает результат fn.
using _ = region.enter()Сделать регион текущим до конца блока.
Region.object(obj), Region.array(...items)Объект или массив в текущем регионе.
#{ key: value }, #[a, b]Объект или массив сразу в текущем регионе, без копии. Нужен флаг --harmony-region-literals.
region.object(obj), region.array(...items)То же в этом регионе, без enter.
region.free(), using region = new Region()Освободить регион: обращения к нему запрещены навсегда, память типизированных массивов отдаётся сразу, объекты опустошаются при сборке.
region.freed, region.byteSize, Region.stats()Освобождён ли регион, сколько байт в него скопировано, и сводка по всем регионам процесса.
spawn(fn, ...args)Запустить функцию в отдельном потоке. См. следующую страницу.
spawn.poolSizeСколько воркеров в пуле spawn, по умолчанию 4.
spawn.idle()Промис, который выполнится, когда закончатся все задачи, запущенные этим потоком.
new Channel(capacity)Канал между потоками: send, recv, close, Channel.select и блокирующие версии. См. страницу про каналы.
