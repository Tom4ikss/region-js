# Changelog

## Unreleased

- Писать прямо в регион: `using _ = region.enter()`, `Region.object()` и `Region.array()` создают объекты в текущем регионе, `region.object()` и `region.array()` — в данном; `run()` тоже делает регион текущим.
- Массивы региона растут и укорачиваются: `push`, `pop`, `splice`, запись за концом, `length = n`. Объекты по-прежнему с фиксированной формой.
- Копирование в регион быстрее: поля обычных объектов читаются напрямую по их map, плотные массивы — из хранилища элементов (200 000 объектов: 269 → ~165 мс).
- Текст ошибки про ссылку наружу региона подсказывает `Region.object()`.
- Литералы `#{ ... }` и `#[ ... ]` под флагом `--harmony-region-literals`: объект создаётся сразу в текущем регионе, без промежуточного объекта и без копии. Внутри — примитивы, объекты того же региона и типизированные массивы (копируются); вложенные объекты пишутся как `#{}`. Пока это вызов рантайма на каждый литерал (~0,5 мкс), быстрый путь в JIT — следующий шаг.
- Объекты одинаковой формы, созданные одним потоком, делят одну map: через `run()`, `Region.object()` и `#{}`, в любом регионе. Раньше у каждого копирования были свои map, и чтение таких объектов было в разы медленнее.
- Исправлено: читатель замороженного массива без билета, попавший на `thaw()` и рост массива у владельца, мог прочитать за концом старого хранилища. Теперь индекс проверяется и по длине, и по размеру загруженного хранилища (тест `tests/thaw-race.js`).

## 0.1.0-alpha

Первая публичная версия. V8 `e16f1ccc` + `v8/regions.patch`, флаг `--harmony-regions`.

**Регионы**
- `new Region()`, `region.run(fn, transfer?)`: простые объекты, массивы, строки, числа и типизированные массивы копируются в общую кучу; классы, `Map`, функции и наследники `Array` отклоняются.
- Владение проверяется на каждом обращении, включая inline caches: чтение из региона почти не медленнее обычного объекта, запись примерно в 6 раз медленнее, доступ по индексу — примерно в 11.
- Переезд `postMessage(msg, [region])` за O(1), `Region.of(obj)`.
- Заморозка: `freeze` / `thaw` / `borrow` / `borrowWhile`, право разморозки передаётся через transfer list.
- TypedArray в регионе: копия или переезд буфера, отсоединение view при переезде, заморозке и разморозке; view замороженного региона живут только под билетом.
- `region.free()`, `using`, `region.freed`, `region.byteSize`, `Region.stats()`.
- Освобождение номеров регионов и памяти typed array после сборки общей кучи.

**Задачи и каналы**
- `spawn(fn, ...args)`: пул воркеров (`spawn.poolSize`), захват переменных из замыкания, `this` и `arguments` стрелок, `join()` и `await` сколько угодно раз, вложенные задачи как `std::thread::scope`, `spawn.idle()`, необработанные ошибки задач сообщаются.
- Свой порт задач вместо `postMessage`, кэш анализа замыканий, ожидание с коротким спином (`--spin-wait-us`, по умолчанию 50): ≈3,5 мкс на `spawn(...).join()`.
- `Channel`: буфер или встреча, `send` / `recv` / `close` / `select`, `for await`, блокирующие версии, передача каналов между потоками; корректная работа с `Worker.terminate()`.

**Инструменты**
- Типы TypeScript, правила Biome и плагин ESLint (`no-floating-spawn`, `no-region-use-while-spawned`, `no-floating-borrow-while`), настройки VSCode.
- Документация на русском с настоящим выводом примеров и бенчмарками.

**Известные ограничения**
- Только d8. Node и Chromium регионы не знают.
- Запись в регион и доступ по индексу не встроены в оптимизирующие компиляторы.
- Сборка общей кучи останавливает все потоки; `free()` возвращает память объектов на ближайшей такой сборке, typed array — сразу.
- Нет поиска зависших каналов: если все ждут канал, в который никто не напишет, d8 ждёт вечно.
- Проверки безопасности уровня настоящего V8 не было.
