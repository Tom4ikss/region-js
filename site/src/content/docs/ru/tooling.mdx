<div class="lead">

Большую часть ошибок с регионами и `spawn` d8 покажет только при запуске. Часть из них можно увидеть раньше, прямо в редакторе. Для этого есть песочница `playground/`: типы, правила Biome и небольшой плагин ESLint. На этой странице — что ловит каждый из них и как их подключить.

## Кто что ловит {/* #layers */}

Проверок три слоя, и у каждого свои возможности. Типы знают, что можно положить в регион и какие у него методы. Biome находит шаблоны в коде, например `class` внутри колбэка `spawn`. ESLint умеет следить за порядком выполнения: что задача запущена, а регион трогают до её конца, или что между проверкой и использованием стоит `await`. Остальное видно только при запуске.

| Ошибка | Чем ловится |
| --- | --- |
| Функция, `Map`, экземпляр класса, `DataView` в `region.run` или в аргументе `spawn` | типы |
| Опечатка в методе региона, новое поле у объекта региона | типы |
| `class`, `eval` или `with` в колбэке `spawn` | Biome, ошибка |
| Метод объекта как колбэк: `spawn(Math.max)` | Biome, ошибка |
| `spawn(...).join()` | Biome, предупреждение |
| Ручку задачи никто не ждёт, в том числе в колбэке `map` | ESLint, [`no-floating-spawn`](#no-floating-spawn), предупреждение |
| Захваченный регион трогают, пока задача идёт; задачи в цикле хотят один регион; задача пишет в замороженный регион | ESLint, [`no-region-use-while-spawned`](#no-region-use-while-spawned) |
| Регион трогают после `send` в канал | ESLint, [`no-use-after-send`](#no-use-after-send) |
| Задача меняет обычный объект или переменную вызывающего, а меняется её копия | ESLint, [`no-write-to-spawn-copy`](#no-write-to-spawn-copy) |
| `await`, пока держат guard `RwLock` или билет `borrow()` | ESLint, [`no-await-holding-guard`](#no-await-holding-guard), предупреждение |
| Ссылка из `guard.value` живёт дольше guard | ESLint, [`no-guard-value-escape`](#no-guard-value-escape) |
| `if (region.frozen)`, потом `await`, потом регион | ESLint, [`no-stale-region-check`](#no-stale-region-check), предупреждение |
| `borrowWhile(async ...)`, промис которого никто не ждёт | ESLint, [`no-floating-borrow-while`](#no-floating-borrow-while) |
| Захваченная переменная с `Map` или функцией внутри, захваченный `this` с методами, захват до инициализации, чужой регион, голый `borrow()` в асинхронной задаче, массив поверх `SharedArrayBuffer` | только при запуске |

## Как подключить {/* #setup */}

1. Откройте папку `playground` в VS Code целиком (File → Open Folder). Типы и правила подключаются из её настроек, отдельный файл они не увидят.
2. Выполните `npm install`: он ставит Biome, ESLint и TypeScript.
3. Поставьте расширения Biome и ESLint. VS Code сам предложит их, они записаны в `.vscode/extensions.json`.
4. Укажите путь к своему d8 в `.vscode/settings.json`, настройка `regions.d8Path`. Тогда Cmd+Shift+B запускает открытый файл командой `d8 --harmony-regions --module --expose-gc --max-serializer-memory=4000 файл.js`.

То же можно проверить из терминала, в папке песочницы:

```sh
$ npm run typecheck      # типы, tsc
$ npm run lint           # правила Biome
$ npm run lint:regions   # правила ESLint для папки examples
$ npm run test:rules     # тесты самих правил ESLint
```

В `examples/mistakes.js` собраны типичные ошибки, и каждая должна подсветиться. Если подсветки нет, начните с этого файла.

:::note[Если поменяли плагин]
Сервер ESLint в VS Code загружает плагин один раз. После правки файлов в `eslint-plugin-regions/` перезапустите его: палитра команд → «ESLint: Restart ESLint Server». Иначе редактор будет показывать старые сообщения или не покажет новые.
:::

## Типы {/* #types */}

Файл `types/regions.d.ts` описывает `Region`, `spawn`, `Channel` и глобальные функции d8 (`print`, `Worker` с его `getMessage`). Встроенный в VS Code TypeScript читает его через `jsconfig.json`, ставить ничего не нужно. Это даёт автодополнение и проверку того, что кладётся в регион: результат `run` и аргументы `spawn` должны быть данными (примитивы, простые объекты, массивы, типизированные массивы, функции из `Region.fn`).

<div class="versus">

```js bad
region.run(() => new Map());
region.frezee();
const state = region.run(() => ({ count: 0 }));
state.total = 1;
```

</div>

```text wrap
error TS2322: Type 'Map<any, any>' is not assignable to type 'RegionData'.
error TS2551: Property 'frezee' does not exist on type 'Region'. Did you mean 'freeze'?
error TS2339: Property 'total' does not exist on type '{ count: number; }'.
```

Последняя ошибка — та же фиксированная форма, что и в d8 ([чтение и запись](/region-js/ru/guide/#rules)): тип результата `run` знает только поля, которые были при создании.

Чего типы не знают. Типизированный массив поверх `SharedArrayBuffer` для них такой же, как любой другой, а d8 его отклонит. Что можно отправить в канал, типы не проверяют: у `Channel` без параметра тип значения `any`.

## Biome {/* #biome */}

Правила Biome лежат в `rules/*.grit` и подключены в `biome.json`. Они ищут шаблоны в коде и не следят за порядком выполнения. Четыре правила повторяют проверки, которые `spawn` делает при вызове, только раньше, в редакторе.

<div class="versus">

```js bad
spawn(() => { class Local {} return Local.name; });
spawn(() => eval('1 + 1'));
spawn(Math.max, 1, 2);
const value = spawn(() => 42).join();
```

</div>

```text wrap
× spawn() callbacks cannot declare classes: their methods cannot be checked and sent to the worker. Use plain objects and functions.
× spawn() callbacks cannot use eval or with: the variables they need cannot be known in advance.
× spawn() needs an arrow function or a function expression; methods cannot be sent to a worker. Wrap it: spawn(() => ...).
! join() blocks this thread until the task ends; on the main thread prefer `await spawn(...)`.
```

Правило про `join()` срабатывает только на цепочку `spawn(...).join()` и не знает, в каком потоке код. В воркере или в коротком скрипте d8 `join()` уместен, и предупреждение можно игнорировать. Почему в главном потоке лучше `await`, показано в [практике 7](/region-js/ru/practices/#await).

## ESLint {/* #eslint */}

Плагин `eslint-plugin-regions/` подключён в `eslint.config.mjs` набором `recommended`. В нём восемь правил. ESLint видит области видимости переменных и порядок выражений, поэтому может сказать «регион уехал в задачу на строке 3, а на строке 4 его читают».

### `regions/no-floating-spawn` {/* #no-floating-spawn */}

Ручку задачи никто не ждёт: ни `await`, ни `join()`, ни возврата из функции. Результат и ошибка такой задачи теряются (ошибку d8 всё же покажет, см. [«Ошибки не теряются»](/region-js/ru/spawn/#unhandled)). Это предупреждение, а не ошибка.

<div class="versus">

```js bad
spawn(() => 1);

await Promise.all([0, 1].map((i) => {
  spawn(() => i * 2);
  return i;
}));
```

</div>

```text wrap
warning  The result of spawn() is neither awaited nor joined, so its value and errors are lost. Use `await spawn(...)`, `.join()`, return the handle, e.g. to Promise.all(), or start the task with `s.spawn(...)` in `spawn.scope(async (s) => ...)`, which waits for it
warning  This callback returns `i`, not the handle of this spawn(), so whoever waits for the callback (e.g. Promise.all over map()) does not wait for the task. Return the handle: `return spawn(...)`, or `return spawn(...).then(() => i)` to keep the value
```

Второй случай — колбэк `map`, который запускает задачу, но возвращает другое значение. `Promise.all` тогда ждёт это значение, а не задачу ([практика 10](/region-js/ru/practices/#map)). Задачи, запущенные внутри другой задачи без `await`, правило тоже отметит, хотя внешняя задача их дождётся ([задачи внутри задач](/region-js/ru/spawn/#nested)).

### `regions/no-region-use-while-spawned` {/* #no-region-use-while-spawned */}

Регион, захваченный задачей или переданный ей аргументом, уезжает в воркер и возвращается, когда задача закончилась. Задачи `s.spawn()` из [`spawn.scope`](/region-js/ru/spawn/#scope) и `set.spawn()` из `JoinSet` правило считает так же. Правило находит три ошибки вокруг этого. Все три в d8 закончились бы `OwnershipError`.

<div class="versus">

```js bad
// 1. Регион трогают, пока задача идёт.
const cart = new Region().run(() => ({ total: 0 }));
const task = spawn(() => { cart.total += 50; });
print(cart.total);
await task;

// 2. Задачи в цикле хотят один и тот же регион.
const counter = new Region().run(() => ({ n: 0 }));
await Promise.all([0, 1, 2].map(() => spawn(() => counter.n++)));

// 3. Задача пишет в замороженный регион.
const cfgRegion = new Region();
const config = cfgRegion.run(() => ({ retries: 3 }));
cfgRegion.freeze();
await spawn(() => { config.retries = 5; });
```

</div>

```text wrap
error  'cart' was moved into the spawn() task on line 3 and comes back only when it finishes: using it here throws OwnershipError. Wait for the task first (await it or call join())
error  This spawn() runs repeatedly and every task wants to move 'counter': only the first one gets it, the next ones throw OwnershipError. Await each task, freeze the region to share it read-only, or give every task its own data
error  'config' is in a frozen region: tasks can read it but writing throws OwnershipError. Thaw it first, or let one task own it instead of freezing
```

Правило понимает, что задача закончилась, если её ждут через `await` (в том числе в `Promise.all`) или `join()`, и что замороженный регион не уезжает, а становится общим. Заморозку оно отслеживает по вызовам `freeze()` и `thaw()` до `spawn`.

Анализ простой, и у него есть границы. Регионом правило считает переменную, созданную через `что-то.run(...)`. Объекты региона, полученные иначе (результат задачи, поле другого объекта, литерал `#{}`), оно не отслеживает. С опцией `checkAllCaptures` оно проверяет все захваченные переменные, но тогда будет ругаться и на обычные данные, которые просто копируются. Обращения из колбэков, которые выполнятся позже (таймеры, обработчики), правило не отмечает: оно не знает, закончится ли задача к тому времени.

### `regions/no-use-after-send` {/* #no-use-after-send */}

`send` отдаёт регион получателю, как `spawn` отдаёт его задаче, только назад он не возвращается. Следующее обращение отправителя падает с `OwnershipError`, и правило показывает его сразу.

<div class="versus">

```js bad
const batch = new Region().run(() => ({ rows: [], total: 0 }));
await out.send(batch);
print('sent', batch.rows.length);
```

</div>

```text wrap
error  'batch' was sent on line 2, and its region moved to the receiver: using it here throws OwnershipError. Use it before sending, or freeze the region to share it read-only
```

Регион здесь тот же, что у правила выше: переменная из `что-то.run(...)`. Замороженный регион канал не отдаёт, а делит, и правило это знает. Отмечается только первое обращение после `send` в той же функции. Обращение в другой ветке `if` или после нового присваивания переменной не считается. Отправку в цикле переменной, объявленной снаружи цикла, правило не видит: второй круг падает уже в d8.

### `regions/no-write-to-spawn-copy` {/* #no-write-to-spawn-copy */}

Обычные объекты и массивы, захваченные задачей или переданные аргументом, копируются в воркер. Задача меняет копию, вызывающий своих изменений не видит, и ошибки нет: просто неверный результат. То же с присваиванием захваченной переменной.

<div class="versus">

```js bad
const stats = { batches: 0 };
await Promise.all([0, 1, 2].map(() => spawn((stats) => { stats.batches++; }, stats)));
print(stats.batches); // 0

let done = 0;
await spawn(() => { done++; });
```

```js good
const stats = new Region().run(() => ({ batches: 0 }));
for (let i = 0; i < 3; i++) await spawn((stats) => { stats.batches++; }, stats);

const done = await spawn(() => 1);
```

</div>

```text wrap
error  'stats' is plain data, so the spawn() task works on its own copy: this change never reaches the caller. Return the result from the task, or create the object in a region (region.run(() => ...)) so that the task gets the object itself
error  'done' is a variable of the caller, and the spawn() task has its own copy of it: this assignment never reaches the caller. Return the value from the task instead
```

Обычными данными правило считает `const` или ни разу не переприсвоенный `let` с литералом `{}` или `[]`, вне функций с `'use region'`. Запись — присваивание поля, `++`, `delete`, `push` и другие меняющие методы массивов, `Object.assign`. Если задача возвращает объект (`return stats`), правило молчит: копию меняют, чтобы вернуть. Параметр функции вызывающего правило не проверяет: откуда он, неизвестно.

### `regions/no-await-holding-guard` {/* #no-await-holding-guard */}

Guard `RwLock`, который держат через `await`, держат всё время ожидания: писатели, а для write-лока и все остальные, стоят в очереди. В `traps/server.js` так 20 запросов из 20 упираются в таймаут. С билетом `borrow()` то же самое: пока идёт ожидание, `thaw()` падает, а `thawWhenFree()` ждёт. Это как `await_holding_lock` в clippy.

<div class="versus">

```js bad
async function handle(req, state) {
  using g = await state.write();
  g.value.inFlight++;
  await sleep(req.cost); // работа под локом
  g.value.served++;
}
```

```js good
async function handle(req, state) {
  { using g = await state.write(); g.value.inFlight++; }
  await sleep(req.cost);
  using g = await state.write();
  g.value.inFlight--;
  g.value.served++;
}
```

</div>

```text wrap
warning  'g' holds the lock across this await: every task that wants the lock waits until the awaited work is done. Do the waiting before taking the lock or after releasing it (end the block of the guard or call release())
warning  'b' keeps the region borrowed across this await: until the awaited work is done thaw() fails and thawWhenFree() waits. Read what you need, release the borrow, then wait
```

Guard, объявленный через `using`, правило считает живым до конца блока, а обычную переменную — до её `release()`. Guard без `using` и без `release()` оно не отслеживает. Отмечается первое `await` под guard, в том числе `for await`, но не `await` в колбэках, которые выполнятся позже. Иногда держать лок через `await` нужно, например чтобы два шага шли без чужих записей между ними, поэтому это предупреждение.

### `regions/no-guard-value-escape` {/* #no-guard-value-escape */}

Объекты `RwLock` доступны, только пока держат guard. Ссылка, вынесенная из `guard.value` за блок, после его конца падает с `OwnershipError: region N is in an RwLock`. Ошибка понятная, но приходит поздно, обычно после `await`.

<div class="versus">

```js bad
async function price(lock) {
  let prices;
  {
    using r = await lock.read();
    prices = r.value.prices;
  }
  await sleep(5);
  return prices.tea;
}
```

```js good
async function price(lock) {
  let tea;
  {
    using r = await lock.read();
    tea = r.value.prices.tea;
  }
  await sleep(5);
  return tea;
}
```

</div>

```text wrap
error  'prices' was taken from 'r.value' on line 5, and the guard is released before this use: it throws OwnershipError. Copy the data you need while the guard is held, or do this work under the guard
```

Без типов правило не знает, объект в переменной или число, поэтому смотрит, как её используют после guard. Обращение к полю, вызов метода, `for...of` и spread — это объект, и правило его отметит. Число или строку можно спокойно выносить, как `tea` выше. Отмечается и `return r.value`: guard отпускается на выходе из функции, и вызывающий получает объект, которым нельзя пользоваться.

### `regions/no-stale-region-check` {/* #no-stale-region-check */}

Пока `await` ждёт, работают другие задачи и другой код этого потока. За это время регион могут разморозить, изменить и заморозить снова. Проверка `region.frozen` до `await` после него уже ничего не говорит, но ошибки не будет: код просто прочитает другие данные.

<div class="versus">

```js bad
const reader = async () => {
  if (region.frozen) {
    await sleep(20);
    using b = region.borrow();
    return cfg.limit; // уже 20, хотя при проверке было 10
  }
};
```

```js good
const reader = async () => {
  await sleep(20);
  if (region.frozen) {
    using b = region.borrow();
    return cfg.limit;
  }
};
```

</div>

```text wrap
warning  'region.frozen' was checked on line 2, but this await lets other code run first: the region can be thawed, changed or frozen again, a lock poisoned or cleared, before the code below uses it. Check again after the await
```

Правило смотрит на `if`, в условии которого есть `frozen`, `frozenHere`, `sealed`, `readers` или `poisoned`, у переменной или у `Region.of(x)`. Оно отмечает первое `await` в ветке, если после него используют ту же переменную или объект, созданный в ней через `run`. Повторная проверка после `await` снимает предупреждение.

### `regions/no-floating-borrow-while` {/* #no-floating-borrow-while */}

`borrowWhile` с асинхронной функцией держит билет, пока не выполнится её промис. Если этот промис не вернуть из задачи и не дождаться, задача закончится раньше, и билет сдадут посреди работы ([подробнее](/region-js/ru/spawn/#borrow)).

<div class="versus">

```js bad
await spawn(() => {
  Region.of(config).borrowWhile(async () => {
    await null;
    print(config.retries);
  });
});
```

```js good
await spawn(() =>
  Region.of(config).borrowWhile(async () => {
    await null;
    print(config.retries);
  }));
```

</div>

```text wrap
error  borrowWhile() returns a promise here and nobody waits for it: a spawn() task ends without waiting, and its borrow is released before this work is done. Return or await it
```

Голый `borrow()` с отложенным чтением правило не видит. Такой билет d8 сдаёт в конце задачи сам и печатает предупреждение в воркере.

## Литералы `#{}` в редакторе {/* #literals */}

Синтаксиса `#{...}` и `#[...]` ([литералы регионов](/region-js/ru/guide/#literals)) нет в JavaScript, поэтому сами по себе инструменты его не знают. Для VS Code в `playground/vscode-region-literals` лежит расширение. Оно подсвечивает `#` как оператор и подключает к TypeScript плагин: тот заменяет `#` перед `{` и `[` пробелом до разбора файла. Длина текста не меняется, поэтому ошибки, подсказки и автодополнение стоят на своих местах, а литерал получает тип такого же обычного литерала. Ставится оно символической ссылкой (команда в README расширения), после чего нужен «Developer: Reload Window».

Одна особенность от самого TypeScript: пустой `#[]` для него — пустой `[]`, то есть `never[]`, и `push` в него подсвечивается как ошибка. Подскажите тип: `/** @type {Order[]} */ (#[])`.

Biome и ESLint литералы не разбирают. В `playground/` файлы с литералами лежат в `experimental/`, который оба пропускают, а TypeScript проверяет. Запускайте их в d8 с флагом `--harmony-regions`.

Без всего этого обходится директива `'use region'` ([подробнее](/region-js/ru/guide/#use-region)): с ней обычные `{}` и `[]` в функции создаются как `#{}` и `#[]`, а для инструментов это обычный JavaScript со строкой-директивой.

## Что видно только при запуске {/* #runtime */}

Некоторые ошибки нельзя найти, не выполняя код:

- захваченная переменная, в которой лежит `Map`, функция или экземпляр класса: типы проверяют аргументы `spawn`, но не захваты. Сюда же захваченный `this` с методами ([this и arguments](/region-js/ru/spawn/#this));
- переменная, захваченная до инициализации, и одно имя с разными значениями в разных функциях ([что spawn отклоняет сразу](/region-js/ru/spawn/#errors));
- обращение к региону, которым сейчас владеет другой поток, если регион пришёл не из `run` в этой же функции;
- чтение замороженного региона без билета, например объекта, который пришёл через `postMessage` или канал;
- голый `borrow()`, переживший задачу, и view типизированного массива, прочитанный до переезда или заморозки.

Линтер здесь только помогает. Защищает от гонок данных сам движок: он проверяет владельца при каждом обращении, сработало правило в редакторе или нет.
